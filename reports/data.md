# Этап 1. Данные

Все цифры ниже получены скриптами `src/data/download.py` (скачивание, идемпотентно) и `src/data/build.py` (разбор, очистка, дедупликация). Подробные счетчики лежат в `data/processed/dedupe_stats.json`. Сырые данные лежат в `data/raw/` и в репозиторий не коммитятся.

Запуск из каталога `final-team`:

```
.venv/bin/python -m src.data.download
.venv/bin/python -m src.data.build
```

## Единая схема

`data/processed/train.parquet` и `data/processed/course_test.parquet`:

| поле | смысл |
|---|---|
| `text` | тело письма (или SMS) после очистки |
| `subject` | тема письма (у SMS пусто) |
| `label` | 1 = спам, 0 = не спам |
| `source` | spamassassin / enron / lingspam / sms / course_test |
| `lang` | en / ru (эвристика по доле кириллицы) |
| `file` | путь к исходному файлу, для трассировки |

Ссылка на тест в `../tasks/FinalHW.txt` (disk.360.yandex.ru/i/gmW0L-4cJdH7ZQ) ведет не на данные, а на docx с текстом задания; в нем указана настоящая ссылка на тестовый набор, ее и использовали. Docx сохранен как `data/raw/course_test/FinalHW_spec_from_link.docx`. В нем же есть таблица критериев, которой нет в LMS: код 2 балла, «точность выше 86%» 2 балла, анализ решений и несколько моделей 2 балла, микросервис или облако 1 балл, ответы на дополнительные вопросы 1 балл.

## Преобразования

1. MIME-разбор (`src/data/emailparse.py`): `email` из стандартной библиотеки, обход всех частей, декодирование base64 / quoted-printable и кодировок из заголовков. Берем `text/plain`; если его нет, `text/html` переводим в текст через BeautifulSoup (выкидываем `script`, `style`, `head`). Вложения пропускаем. Тема декодируется из RFC 2047.
2. Утечка метки через заголовки: из заголовков оставляем только `Subject`. Остальные (`Received`, `Return-Path`, `X-Spam-*`, `List-*`, конверт mbox `From ...`) выбрасываем: они указывают на корпус-источник или на вердикт фильтра. Из темы удаляем метки вида `*****SPAM*****`, `[SPAM]`, из тела строки `SPAM:` и `X-Spam-`.
3. Очистка текста: HTML-сущности, схлопывание пробелов и пустых строк.
4. Удалены 51 пустое сообщение.
5. Точные дубликаты: ключ = md5 от последовательности токенов `[a-z0-9]+` темы и тела. Так совпадают и сырые письма, и токенизированные Enron / Ling-Spam. Если у одного ключа разные метки, удаляется вся группа (8 сообщений), иначе остается первое (удалено 4385, больше всего внутри Enron).
6. Почти-дубликаты: MinHash (64 перестановки) по шинглам из 5 токенов, LSH с порогом Жаккара 0,85, поиск по всем источникам сразу. Удалено 1518.
7. Пересечение с тестовым набором курса: обучающие письма, точно или почти совпадающие с любым письмом теста, удалены (1499 штук). Это важно: тестовый набор в основном собран из того же SpamAssassin, без этого шага модель видела бы тест на обучении.
8. На этапе признаков (`src/models/features.py`, одинаково при обучении и в сервисе): нижний регистр, URL -> `urltoken`, e-mail -> `emailtoken`, цифры -> `0`, пробелы вокруг пунктуации, удаление символов нулевой ширины, обрезка до 6000 символов. Это выравнивает «сырые» письма и заранее токенизированные Enron / Ling-Spam, иначе символьные n-граммы выучили бы форматирование корпуса, а не спам.

## Тестовый набор курса

Архив `test_task_emails.tar.xz` (1,9 МБ), 1600 файлов `.eml`: `ham/` 600, `spam/` 1000. Метки есть (по папке). Письма сырые, с полными заголовками, MIME, HTML, разные кодировки, поэтому прогоняются через тот же разбор, что и SpamAssassin (`course_test.parquet`).

Происхождение по конверту mbox и заголовкам:

| | ham | spam |
|---|---|---|
| SpamAssassin 2001-2002 (конверт `From ... 2002`) | 543 | 590 |
| фишинг с конвертом `From nobody ... 2015` (по виду корпус фишинга J. Nazario: PayPal, eBay, банки) | 0 | 304 |
| без конверта (в т.ч. свежие русскоязычные письма) | 57 | 106 |

По языку: 35 писем на русском (13 ham, 22 spam), остальные на английском. Медиана длины тела 982 символа, у 18 писем тело пустое (только тема или картинка).

Следствия для модели:
- тест сильно пересекается со SpamAssassin, поэтому обучающая выборка от него очищена (п. 7 выше);
- около 30% спама в тесте это фишинг, которого почти нет в обучающих корпусах;
- русских писем в обучении нет совсем, на них модель работает хуже (вопрос о мультиязычности со слайда 16).
